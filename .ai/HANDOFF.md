# Handoff

Run `uv sync --locked` to set up the environment, `uv run --locked python -m dockside.server` to start the service, and `uv run --locked python -m unittest discover -v` to run the suite. Open `http://127.0.0.1:8765` in Chrome. The README includes a typed workspace smoke procedure.

The browser assets are in `dockside/static/`. The chooser fetches `GET /api/problems`. The shared submission flow calls `POST /api/interview` with same-origin JSON containing `problem_id`, `intent` (`reply`, `check`, or `finish`), `code`, and `text`, then displays the returned `reply`. The route uses local Ollama (`qwen3:4b`). Browser history lives in per-problem sessions. The workspace includes up to six recent messages from the selected problem as optional `history`. The server validates each candidate or interviewer message against a 400 UTF-8 byte limit and gives Ollama the transcript with the current code snapshot.

Manual recording in `workspace.js` uses MediaRecorder, caps capture at 25 seconds, closes the microphone before posting the Blob to `POST /api/transcribe`, and appends any transcript to the draft. Sending the draft captures the editor at send time. Hands-free capture uses that same lifecycle plus the detector in `turn-detection.mjs`. It discards idle windows and resumes after the interview request settles. The awaited submission in the capture flow is the integration point for keeping capture closed through playback. See `docs/history/005-recording-upload.md` for media formats, response statuses, and limits.

For playback, send the interviewer reply as UTF-8 `text/plain` to `POST /api/speech` and play the returned WAV Blob. The current engine uses macOS `say`. Keep capture paused through playback or failure, and keep the reply visible if synthesis or playback fails. See `docs/history/006-local-playback.md` for limits and statuses.

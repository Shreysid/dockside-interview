# Handoff

Follow the README to install dependencies, start Ollama, download the local models, and set up the locked environment. Use its offline launch command once setup is complete. Open `http://127.0.0.1:8765` in Chrome. The README includes test commands and browser smoke procedures.

The browser assets are in `dockside/static/`. The chooser fetches `GET /api/problems`. The shared submission flow calls `POST /api/interview` with same-origin JSON containing `problem_id`, `intent` (`reply`, `check`, or `finish`), `code`, and `text`, then displays the returned `reply`. The route uses local Ollama (`qwen3:4b`). Browser history lives in per-problem sessions. The workspace includes up to six recent messages from the selected problem as optional `history`. The server validates each candidate or interviewer message against a 400 UTF-8 byte limit and gives Ollama the transcript with the current code snapshot.

Manual recording in `workspace.js` uses MediaRecorder, caps capture at 25 seconds, closes the microphone before posting the Blob to `POST /api/transcribe`, and appends any transcript to the draft. Sending the draft captures the editor at send time. Hands-free capture uses that same lifecycle plus the detector in `turn-detection.mjs`. It discards idle windows and resumes after the interview request and optional playback settle. See `docs/history/005-recording-upload.md` for media formats, response statuses, and limits.

The **Speak interviewer replies** checkbox activates a Web Audio context in Chrome. The turn handler renders the text immediately, sends the reply as UTF-8 text/plain with the selected X-Dockside-Voice header to POST /api/speech, and waits for the decoded WAV to finish. Audio errors leave the transcript and finish state usable. The endpoint lazily loads the local Kokoro-82M INT8 model with Heart, Bella, or Michael at 0.96× speed and returns 24 kHz mono PCM WAV. Preview uses the same playback flow and is available once the microphone is closed. Push-to-talk shares the recorder lifecycle and sends on release. A fresh loopback smoke test verified real transcription, a reply, final feedback, and valid Kokoro WAV output. Physical microphone and native permission-dialog QA remain pending.

The interviewer prompt and Ollama reply budgets live in `dockside/interviewer.py`. Standard turns have a shorter generation budget than final feedback.

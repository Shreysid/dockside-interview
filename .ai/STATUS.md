# Project status

Dockside serves a responsive typed interview workspace at the loopback origin. It loads a three-problem catalog, holds a separate draft and transcript for each problem while the page is open, submits the current code with each typed, check, and finish action, and displays final feedback.

The locked uv environment and HTTP tests cover typed turns, the catalog, static assets, and the loopback access policy. Chrome can record and transcribe short microphone clips into an editable response draft. Opt-in hands-free capture sends a turn after sustained speech and 1.8 seconds of quiet, or on manual send. Typed, recorded, check, and finish turns use bounded conversation context from the active problem. Chrome can speak interviewer replies and finish feedback using the local speech endpoint. Hands-free capture stays closed through synthesis and playback. Spoken output uses local Kokoro-82M INT8. Headless Chrome verified a silence-triggered turn through real Whisper, Ollama, and Kokoro using a synthetic audio stream. Capture resumed after playback. Physical microphone and permission-dialog QA remain pending.

The browser offers the Heart, Bella, and Michael Kokoro presets at 0.96× speed. Heart is the default. Preview works with spoken replies off and is available only when recording is stopped and hands-free mode is paused. Headless Chrome played all three previews and a reply using real Kokoro audio, a stubbed interviewer, and a synthetic microphone. Preview was disabled during capture and all tracks had ended before playback.

Push-to-talk accepts pointer, Space, and Enter holds. Release sends a transcribed reply automatically, and cancellation closes any tracks delivered by a pending permission request. The code editor stays editable during processing and playback. Headless Chrome verified push-to-talk with a synthetic microphone and stubbed turn endpoints.
